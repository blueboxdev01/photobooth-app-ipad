# v0.19.1 — Pickup by number, and a MacBook booth

> **Use v0.19.1, not v0.19.0.** The v0.19.0 tag failed one test on Windows (a test that assumed
> Mac line endings, not a fault in the booth), so it has no Windows download. The two builds
> have the same features.

**Windows: `photobooth-v0.19.1-win-x64.zip`. Mac (Apple Silicon): `photobooth-v0.19.1-macos-arm64.zip`.**
Unzip and run `Photobooth.Server.exe` (Windows) or `./Photobooth.Server` (Mac), then open
<http://localhost:5000/operator>.

> The Mac build is unsigned. After downloading, run `xattr -dr com.apple.quarantine <folder>`
> once. It needs `brew install ffmpeg` for the guest video.

Start with **[docs/EVENT-SETUP.md](../EVENT-SETUP.md) section 1b** and the test sheet,
**[docs/WEDNESDAY-TEST.md](../WEDNESDAY-TEST.md)**.

## Pickup by number

Guests are now given a **number** at Accept, instead of being shown a photos QR.

1. The guest's strip shows on the monitor. Staff press **Accept**.
2. The monitor shows a large **number** (1, 2, 3..., restarting each day) and *Tell this number at
   the claiming station*. The number is also stamped on the strip as **No. N**.
3. At the **claiming station**, the operator opens **Claiming Station**, types the number, hovers
   the guest's strip, and clicks **Show QR**. The guest scans it and downloads their photos, strip
   and video.

Turn it on with **Settings > Guest photos over your wifi > Hand over by number**.

## The claiming station is a second computer

The Windows laptop reads the booth Mac's **shared sessions folder** (SMB) and lists every guest by
number. On it, switch on **This computer is the claiming station only**: it starts no camera and
hides Start Session. It serves the download page to phones, so it must be on the booth wifi.

The list of guests carries every guest's link, so it is on the operator's own screen only and
**is refused on the network ports**.

## The booth runs on a Mac

The same app runs on a MacBook. The camera is unchanged: Canon's EOS Utility saves into a folder
and the booth watches it.

- The booth's certificate key and the Google Drive token are kept in owner-only files on a Mac,
  rather than with Windows encryption. Keep **FileVault** on.
- The guest video uses the Mac's own H.264 encoder.
- `tools/mac-display.command --local` opens the guest screen fullscreen on the Mac's external
  monitor, with no iPad, certificate or HTTPS.
- Folder paths accept `~/`, and the Settings examples follow the machine you are on.

## One QR, not two

The guest screens no longer show a join-wifi QR. That code is on **Settings**, to print for a sign
by the queue.

## Not yet verified

- **EOS Utility on macOS 27.** Canon's latest build lists macOS 26, 15 and 14.
- **A real Mac sharing to a real Windows laptop**, in particular whether a guest can appear on the
  claiming station before all their files have arrived.
- **4 photos per strip drops the frame art.** The shipped frame has three windows. Setting four
  gives a plain strip with the number at the foot; a 4-window frame needs new art.
- **The Mac release workflow** (`release-mac.yml`) has not run on GitHub before this tag.

## Also changed

- Numbers restart each day. To restart mid-day, delete the test session folders and restart the app.
- The video is still an MP4, not a GIF, because Instagram and Facebook accept MP4.
