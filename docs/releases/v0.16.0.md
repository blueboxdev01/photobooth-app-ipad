# v0.16.0-ipad — The iPad stops showing a preview that was never the photo

**Download `photobooth-v0.16.0-win-x64.zip`, unzip, run `Photobooth.Server.exe`.**
Then open <http://localhost:5000/operator>.

> The version at the foot of the rail reads **`0.16.0-ipad`**. Please quote it
> with any result.

## The posing mirror has gone

You reported that what the iPad showed was not what the camera took. It wasn't,
and it couldn't be.

The mirror was the **iPad's own front camera**. It sits wherever the iPad is
propped, at its own angle with its own lens, while the photograph is taken by the
R50 standing somewhere else. The two were never going to agree, and a guest
posing to the iPad was framing a shot nobody was taking. A preview that
disagrees with the photograph is worse than no preview.

So the screen now shows only what the booth actually knows.

| | The iPad shows |
|---|---|
| Between guests | **Step in and smile**, and the empty photo slots |
| Counting down | **the number, filling the screen** |
| Taking photos | *Hold it…*, and each shot as it lands |
| Review | the shots, large enough to judge across a booth |
| Finished | **the strip and its QR code** |

The countdown is much bigger than it was — it used to share the screen with the
video and now it *is* the screen.

## What this changes for you

**The iPad no longer has to sit near the lens.** It was positioned where the
webcam used to be because it was a camera. Now it only has to be somewhere the
guests can read it, which is a much easier thing to find room for.

**Nothing about setup changes.** The certificate, the trust step and the HTTPS
address all stay exactly as they are — see below.

**Guests get no framing preview at all now.** That is the honest trade. If people
crowd in and lose their shoulders off the sides of the strip, the fix is marking
the floor where they should stand, not putting the preview back.

## Why you still need the certificate

The old guide said the mirror was the whole reason an iPad needs HTTPS. That is
no longer true, and it was worth checking before anyone acted on it: the **wake
lock** needs a secure context too, and without it the iPad dims and then sleeps
during an event, which looks exactly like a dead booth.

So the certificate stays. If you would rather not install it, the other way to
solve the same problem is **Settings → Display & Brightness → Auto-Lock →
Never** on the iPad, which the runbook already tells you to set anyway.

## What to look at

1. **Run a session with the iPad up.** Countdown, then each shot appearing, then
   the review, then the strip and QR. Nothing should be missing between them.
2. **Read the countdown from where a guest stands.** It should be the easiest
   thing in the room to read.
3. **Check where guests end up in frame.** With no preview to pose against, this
   is the thing most likely to need a change — tell us if people are consistently
   too close.
4. **Leave the iPad idle fifteen minutes.** It should not dim or sleep.

The **Preview — webcam** picker has gone from Settings, since there is no longer
anything for it to feed.

## Everything else

Unchanged from v0.15.0: the flat session times, the synchronised countdown, the
photos that save straight to a camera roll, the looping GIF, the MemoStills
console and the Guest Gallery.

Still outstanding, unchanged: a custom backdrop set in Settings does not reach
the iPad, which keeps its default dark background.
