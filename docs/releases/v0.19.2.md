# v0.19.2 — Photos in EOS Utility's dated folders are now picked up

> **Use v0.19.2, not v0.19.1.** In v0.19.1 a session could sit at *waiting for photos* with the
> camera connected and every shutter press landing a file, because the booth never saw them.

**Windows: `photobooth-v0.19.2-win-x64.zip`. Mac (Apple Silicon): `photobooth-v0.19.2-macos-arm64.zip`.**
Unzip and run `Photobooth.Server.exe` (Windows) or `./Photobooth.Server` (Mac), then open
<http://localhost:5000/operator>.

> The Mac build is unsigned. After downloading, run `xattr -dr com.apple.quarantine <folder>`
> once. It needs `brew install ffmpeg` for the guest video.

Start with **[docs/EVENT-SETUP.md](../EVENT-SETUP.md) section 1b** and the test sheet,
**[docs/WEDNESDAY-TEST.md](../WEDNESDAY-TEST.md)**.

## The fix

Canon's EOS Utility saves each day's shots under a **dated subfolder** of its destination folder,
for example `Photobooth/2026_10_28/IMG_0001.JPG`. The booth only looked at the top level of the
watch folder, so real shots were saved but never ingested. Only mock photos, which land at the top
level, worked.

The booth now watches the watch folder **and every folder inside it**, both live and in the
periodic sweep.

Because of that, **Settings now refuses an output folder that sits inside the watch folder**, as the
finished strips would be picked up as new photos. Keep the two folders apart.

## Everything else is as v0.19.1

Pickup by number, the Claiming Station page, the Mac booth and the single end-of-session QR are
unchanged. See [v0.19.1](v0.19.1.md).
