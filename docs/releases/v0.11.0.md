# v0.11.0-ipad — The guest display is an iPad

**Download `photobooth-v0.11.0-win-x64.zip`, unzip, run `Photobooth.Server.exe`.**
Nothing to install — no .NET, no Node. Exactly as before.

Then open <http://localhost:5000/operator>.

> **This is a variant build, not the next version of the app you have been
> testing.** It comes from a separate repository. The build you already have,
> **v0.10.0**, is still the main line and is unaffected by anything here.
>
> The version at the foot of the rail reads **`0.11.0-ipad`** so the two cannot
> be confused. Please quote it with any result.

## What is different

**The guest display can be an iPad instead of an external monitor** — and the
**iPad's front camera becomes the posing mirror**, so there is no separate USB
webcam.

Everything else is v0.10.0: the same capture, review, retake, reordering,
compositing, local archive and Drive delivery.

## What you need to test it

| | |
|---|---|
| **An iPad** | iPadOS **16.4 or newer**. Without one, this build behaves exactly like v0.10.0 |
| **A network you control** | Your own router, or the laptop's hotspot. **Not a venue or office wifi** — see below |
| **A stand for the iPad** | Its front camera is now the mirror, so it sits where the webcam did: facing the guests |

The booth and the iPad must be on the **same network**. No internet is needed
unless you turn on Google Drive.

## Setting it up

**`IPAD-DISPLAY.md`, in the ZIP.** Twenty minutes the first time, most of it on
the iPad.

The short version:

1. **Setup → Guest display on an iPad → Serve the display to an iPad**, then
   **restart the booth**.
2. Scan the **first QR code** on the iPad, install the certificate, then turn it
   on under **Settings → General → About → Certificate Trust Settings**.
3. Scan the **second QR code** to open the display.

Padlock in Safari, and your own face in the mirror, means it is working.

## Why there is a certificate step at all

A browser will not give a web page the camera unless the page is served over
**HTTPS**. The posing mirror is a camera, so an iPad opening a plain `http://`
address gets no mirror at all, and no setting on the iPad changes that.

No public certificate authority will issue a certificate for a laptop on your
wifi, so **the booth issues its own** and the iPad is told once to trust it.
Once done, it stays done — restarting the booth, changing network or changing IP
needs nothing repeated.

> **Installing the certificate and trusting it are two separate steps**, and the
> second is the one everyone misses. If the display refuses to load, that is
> almost certainly why — Safari's error does not mention certificates.

## Two things likely to trip you up

**Most shared wifi separates its devices from each other.** Office and venue
networks commonly do this, and it blocks the iPad from reaching the booth
entirely — no setting in the app can get round it. If the iPad cannot connect at
all, try the laptop's hotspot before assuming anything is broken.

**Windows will ask about the firewall** the first time the app opens its network
ports. Say yes, and make sure **Private networks** is ticked.

## What is served to the network

Only the guest display. The operator console, the template editor, the setup page
and every control that can start or abort a session stay on the booth machine and
are **refused** on the network ports. Worth confirming — Section 8b of
`QA-CHECKLIST.md` has you try to reach them from the iPad and check that you
cannot.

## Please also check

- **The framing guide needs recalibrating.** The iPad's lens is a different field
  of view from the webcam's, and it was never calibrated against the R50 anyway.
  Stand to fill the brackets, take a shot, and tell us how far out it is.
- **Leave the iPad idle for fifteen minutes.** It should not dim or sleep.
- **Turn the wifi off mid-session.** The guest screen will freeze; the session
  itself should complete with the photos intact. The fallback is to plug in a
  monitor and open `/display` on the laptop, exactly as in v0.10.0.

## Still true

- **The app cannot fire the shutter.** The countdown is advisory: the guest sees
  "3-2-1" and you press the remote.
- **Everything about the camera is still an assumption.** File naming,
  extensions, timings — none of it has met a real R50.
- **No printing, no self-serve kiosk.** Neither is built.
- Windows SmartScreen will warn about an unsigned binary. *More info → Run anyway*.
- You need a **DR-E18 / LP-E17 dummy battery**: the R50 will not power itself
  over USB-C while tethered.

## Verification so far

233 automated tests pass, including the certificate rules iOS enforces and the
list of what the network port will and will not serve.

**None of it has touched a physical iPad.** That is what this build is for.
