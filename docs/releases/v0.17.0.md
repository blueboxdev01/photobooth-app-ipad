# v0.17.0-ipad — A video guests can actually post

**Download `photobooth-v0.17.0-win-x64.zip`, unzip, run `Photobooth.Server.exe`.**
Then open <http://localhost:5000/operator>.

> The version at the foot of the rail reads **`0.17.0-ipad`**. Please quote it
> with any result.

## The GIF is now an MP4

Guests could not post the looping GIF. Instagram and TikTok accept no GIF at
all, and Facebook's phone picker turns one into a still. All of them take a
short H.264 video, so that is what the booth makes now.

It is the same strip with the photos rotating through the slots, repeated to
about six seconds. A video does not loop by itself once it has been posted, and
Instagram refuses anything under three seconds.

On the guest page the video plays in place. To post it, a guest **taps it, uses
the share button and chooses Save Video**, then picks it from their camera roll.
The page says so.

The setting is now **Settings → Looping video**, and the operator console lists
it as **Video**. Sessions already taken keep their GIF and still show.

## What changed in the download

**The ZIP is bigger.** It now carries `ffmpeg\ffmpeg.exe`, which is what writes
the video. Leave that folder where it is; the booth looks for it beside the app.

It uses an LGPL build of ffmpeg, which has no `libx264`, so the video is
encoded by **Windows' own H.264 encoder**. That is built into Windows but not
into the "N" editions, which lack the media components.

If the video cannot be made for any reason, the guest still gets the strip and
every photo and the session carries on. They just have no video.

## What to look at

1. **Run a session and open the guest page on an iPhone.** The video should
   play on its own, without a tap.
2. **Tap it and save it.** Share → Save Video should put it in Photos.
3. **Post it** to Facebook and Instagram from the camera roll. This is the whole
   point of the release, and it has not been tried yet.
4. **Check how long a session takes** to reach the QR. Encoding adds a second or
   two; tell us if it is more.

## Not yet verified

This build was written without a Windows machine to run it on. The release
workflow runs the tests and checks the bundled ffmpeg has an H.264 encoder, but
nobody has yet watched a real video come out of a real booth.

## Everything else

Unchanged from v0.16.0: the iPad display with no preview, the synchronised
countdown, the photos that save straight to a camera roll, the MemoStills
console and the Guest Gallery.

Still outstanding, unchanged: a custom backdrop set in Settings does not reach
the iPad, which keeps its default dark background.
